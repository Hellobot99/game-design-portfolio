01 · RaidMyDungeon

액션 + 던전 빌딩 · PC (웹 프로토타입) · 2026.07 ~ · 5인 팀 · 기획 전담
던전을 짓고 남의 던전을 터는 비동기 PvP 게임. 기획서를 시스템 · 콘텐츠 · 밸런스 · 제작 네 갈래로 나눠 쓰고, 같은 수치로 돌아가는 웹 프로토타입과 밸런스 시트로 숫자를 확인했습니다. 클라이언트 2명, 모델링과 애니메이션 각 1명이 함께합니다.
  • 시스템: 플레이마다 얻는 중심 자원을 하나씩 정하고, 남의 던전을 터는 규칙과 악용을 막는 장치(올리기 전 주인 직접 클리어, 같은 침입자는 하루 한 번만 보상, 서버의 공략 기록 검사)를 설계
  • 기획서: 시스템 기획서 19편을 규칙 · 예외 · 플로우 순서로 써서 개발자가 바로 옮길 수 있게 하고, 화면마다 버튼의 기능과 이동할 곳을 정리
  • 밸런스: 영웅 7명을 직접 플레이하며 클리어 시간을 재고 스킬 보정을 다섯 번 고쳐 목표 범위에 맞춤
  • 성장 · 경제: 성장 총량을 먼저 정해 경로마다 나누고, 골드 하루 생산 대비 필요량을 2.6배에서 1.08배로 맞춤
  • 기록: 찾은 문제와 정한 것 24건을 날짜와 이유와 함께 결정 기록으로 남김

02 · Netrunner's Playlist

사이버펑크 방치형 성장 · 모바일 (Unity + C++ IOCP 서버) · 2026.01 ~ · 2인 · 기획 + 서버
해커가 거대 기업의 서버를 하나씩 뚫어 가는 방치형 게임. 기획과 서버를 맡았습니다. 기획서를 시스템과 밸런스 중심으로 다시 정리하고, 서버 코드와 데이터를 대조해 문제를 찾은 뒤 공식과 수치를 새로 설계해 시뮬레이션으로 확인했습니다.
  • 진단: 코드와 데이터를 대조해 수치 문제 16건을 찾음 (경험치 요구량 역전, 보스 HP 톱니 곡선, 지급되지 않는 레벨업 보상 등)
  • 시스템: 포맷(환생) 때 지울 것과 남길 것을 나누고, 데이터를 기획 표 · 저장 데이터 · 밸런스 로그로 분리해 ID 대역과 테이블을 설계
  • 공식: 돈(CPS)과 힘(DPS)을 분리하고, 곱으로 키우되 전체 배율 10배 이후엔 로그로 감속. 비용과 보상은 "CPS 몇 분치"로 정의
  • 목표에서 거꾸로: 하루 2번 × 20분 접속 기준으로 첫 포맷 약 72시간, 10회차에 티어 100, 오프라인 수입 위주(효율 80%)
  • 검증: Python 시뮬레이터로 10회차를 돌려 이전 지점 복귀 시간이 48시간에서 12시간으로 줄어드는 것을 확인하고, 수식이 연결된 엑셀 10개 시트로 정리

03 · 메이플스토리 스타포스 역기획

상용 라이브 게임 · 강화 시스템 · 개발 전달용 기획서 · 2026.10
메이플스토리 스타포스를 개발자에게 넘기는 기획서처럼 다시 정리했습니다. 규칙과 예외를 표로 쓰고, 데이터 테이블을 설계하고, 기대 비용과 불운을 계산한 뒤 개선안을 숫자로 검증했습니다.
  • 규칙 · 플로우: 판정 전에 거를 것(처리 중 · 흔적 · 최대 성 · 메소)과 서버에서 한 번에 처리할 것(차감 · 판정 · 저장)을 나눔
  • 데이터: 값이 바뀌는 때(기획 · 운영 · 저장)와 키로 테이블 10개를 나누고, 규칙 18개가 전부 표현되는지 대조
  • 수치 분석: 250제 0 → 22성 평균 194억, 불운 상위 1%는 463억. 비용의 3분의 2가 17 → 20성에 몰림
  • 비교: 로스트아크(장인의 기운) · 던파(보호권)와 비교해, 스타포스가 불운에 끝을 두지 않는 선택을 했다는 점과 장단점 정리
  • 개선안: 당긴 만큼 확률과 1회 비용을 함께 올리는 확률 슬라이더. 평균 소각은 그대로, 불운 격차 절반(269억 → 129억), 파괴 1회 아래
